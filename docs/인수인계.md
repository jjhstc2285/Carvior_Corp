# 애니원모터스 통합관리 — 인수인계 문서

이 문서 하나로 **배포하고, 설정을 고치고, 숫자가 어디서 나왔는지 되짚을 수** 있게
적었습니다. 코드를 읽지 않아도 운영은 되도록 썼고, 코드를 읽어야 하는 자리에는
어느 파일인지 적어 두었습니다.

작성 시점 기준입니다. 이후 코드가 바뀌면 이 문서보다 코드가 맞습니다.

---

## 1. 시스템 구성

| | |
|---|---|
| 주소 | https://skv1motors.com |
| 서버 | AWS EC2 1대 (Ubuntu) |
| 웹(프론트) | React + TypeScript, 빌드 결과를 Apache 가 `/var/www/skv1motors` 에서 서비스 |
| API | NestJS, PM2 로 `anyone-api` 이름으로 상주 |
| DB | MySQL (같은 서버) |
| 캐시·실시간 | Redis (알림·접속 상태) |
| 파일 | 서버 로컬 디스크. Apache 가 `/uploads` 주소로 서비스 |

### 중요 — 파일 백업이 없습니다

계약서 사진, 차량 사진, 근태 증빙은 **그 서버 디스크 한 곳에만** 있습니다.
S3 같은 외부 보관소에 복제하지 않습니다. 디스크가 날아가면 사진은 복구할 수
없습니다. DB 는 백업이 돌고 있는지 서버에서 한 번 확인해 두시길 권합니다.

> 대응이 필요하시면 `aws s3 sync` 를 하루 한 번 도는 cron 으로 거는 것이 가장
> 간단합니다. 코드 변경 없이 서버 설정만으로 됩니다.

## 2. 배포 절차

서버에 접속해서 아래 한 줄이면 끝납니다.

```bash
cd ~/anyone-motors && ./deploy.sh
```

`deploy.sh` 가 순서대로 합니다.

1. `git pull` — 코드를 받습니다
2. 의존성 설치 — `package-lock.json` 이 바뀐 경우에만 (매번 돌면 1분씩 날아갑니다)
3. 프론트 빌드 → `/var/www/skv1motors` 로 복사
4. `prisma generate` → `prisma migrate deploy` — **DB 구조 변경을 적용합니다**
5. API 빌드 → PM2 재시작

### 옵션

| 명령 | 쓸 때 |
|---|---|
| `./deploy.sh --front` | 화면만 바뀐 경우 |
| `./deploy.sh --api` | 서버 로직·DB 만 바뀐 경우 |
| `./deploy.sh --skip-pull` | 이미 `git pull` 을 한 경우 |

### 배포가 멈추면

- **`server/.env 가 없습니다`** — `.env.example` 을 복사해 값을 채우세요(아래 4장)
- **`server/dist/main.js 가 없습니다`** — 빌드가 실패한 것입니다. **이때 재시작하지
  않고 멈추는 것이 정상입니다.** 예전에 이걸 안 막아서 PM2 가 752회까지 재시작을
  반복한 적이 있습니다. 위로 올라가서 빌드 오류를 먼저 보세요.

### 배포 후 확인

브라우저에서 **Ctrl+Shift+R**(강력 새로고침). 안 하면 예전 화면이 캐시로 남습니다.

```bash
pm2 list              # anyone-api 가 online 인지
pm2 logs anyone-api   # 뜰 때 로그 — 텔레그램 방 연결 여부가 여기 찍힙니다
```

Prisma 로 관리합니다. 모델이 **57개** 있습니다. 구조는

### DB 구조를 바꿀 때 — 꼭 지켜야 하는 것

**운영 DB 에 직접 `ALTER TABLE` 을 치지 마세요.** 반드시 마이그레이션 파일로
남겨야 합니다. 안 그러면 다음 배포에서 Prisma 가 "구조가 다르다"며 멈춥니다.

```bash
cd server
npx prisma migrate dev --name 무엇을_바꾸는지   # 로컬에서 파일 생성
# 생성된 SQL 을 확인한 뒤 커밋 → 배포하면 운영에 적용됩니다
```

마이그레이션 파일은 `server/prisma/migrations/` 에 날짜순으로 쌓여 있습니다.
**이미 배포된 파일은 고치지 마세요** — Prisma 가 내용 검사를 해서 멈춥니다.
잘못 넣었으면 되돌리는 마이그레이션을 새로 추가합니다.

## 4. 설정값 (`server/.env`)

`.env` 는 **git 에 없습니다.** 서버에만 있습니다. 항목 이름과 설명은
`server/.env.example` 에 있고, 값은 없습니다.

### 꼭 있어야 하는 것

| 이름 | 뜻 |
|---|---|
| `DATABASE_URL` | MySQL 접속 주소 |
| `JWT_SECRET` | 로그인 토큰 서명 키. **바꾸면 전원 로그아웃됩니다** |
| `REDIS_HOST` `REDIS_PORT` `REDIS_PASSWORD` | Redis |
| `PORT` `CORS_ORIGINS` | API 포트, 허용할 웹 주소 |
| `UPLOAD_DIR` | 업로드 저장 위치 (기본 `./uploads`) |

### 화면 잠금 번호

| 이름 | 어느 화면 |
|---|---|
| `PROPERTY_ACCESS_CODE` | 부동산 정보 · 상조회비 · 경조사비 |
| `PAYROLL_ACCESS_CODE` | 인건비 · 애니원모터스 모니터링 |

> 번호는 **`.env` 에만** 둡니다. 코드에 박으면 소스를 받은 사람이 전부 봅니다.
> 바꾸고 싶으면 `.env` 를 고치고 `pm2 restart anyone-api` 하면 됩니다.

### 알림·연동

| 이름 | 뜻 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 봇 열쇠. **아는 사람은 누구나 그 봇으로 글을 씁니다** |

| `CHANNELTALK_*` | 채널톡 상담 연동 |

| `PARKBOARD_URL` `PARKBOARD_CODE` | 현장 주차 현황판 |

## 5. 권한 — 누가 무엇을 보나

화면에서 메뉴를 감추는 것만으로는 막은 게 아닙니다. **서버가 같은 기준으로 다시
봅니다.** 한쪽만 고치면 메뉴는 보이는데 눌러도 안 되거나, 그 반대가 됩니다.

### 자리로 가리는 것

| 화면 | 볼 수 있는 사람 |
|---|---|
| 부동산 정보 | 대표·사무장 (+ 번호) |
| 상조회비 · 거래처 | 대표·사무장·본부장 |
| 경조사비 | 관리자 (+ 번호) |
| 인건비 | 대표·**사무장** (+ 번호) |
| 애니원모터스 모니터링 | **대표만** (+ 인건비와 같은 번호) |
| 입금방 | 전 직원 |
| 플랫폼 매물 점검 | 대표·광고팀 |
| 매입 정산 | 계약팀·관리자 (+ 아래 이름 목록) |

### 이름으로 못 박은 것 — `server/src/settlements/approvers.ts`

직급으로 가리면 같은 직급이 하나 더 생겼을 때 그 사람도 돈을 보게 됩니다.
그래서 이름으로 적어 두었습니다. **사람이 바뀌면 이 파일을 고쳐야 합니다.**

| 상수 | 지금 값 | 뜻 |
|---|---|---|
| `CHIEF_APPROVER` | 안원용 | 1차 결재(본부장) |
| `CEO_APPROVER` | 유진욱 | 2차 결재(대표). 여기까지 찍혀야 확정 |
| `CEO_ONLY_OWNERS` | 이우주, 진후 | 이 사람 건은 본부장을 건너뛰고 대표만 |
| `SETTLEMENT_VIEWERS` | 이우주, 안원용, 이태희, 김진후 | 매도정산(신차/개인)을 보는 사람 |
| `REFERRAL_LEADERS` | 김진후 | 알선팀원 정산 전체 열람 + 현금 확인 |

> **화면 쪽에도 같은 목록이 있습니다** (`src/lib/permissions.ts`).
> 한 곳만 고치면 어긋납니다. 둘 다 고치세요.

### 알선 정산의 두 가지 규칙

- **본인 것만 봅니다.** 받아온 사람이 곧 정산받을 사람이라 남의 몫이 보일 이유가
  없습니다. (관리자·알선팀장은 전체)
- **'작성 중'(결재 올리기 전)은 적은 사람만 봅니다.** 적다 만 숫자가 윗사람
  화면에 뜨면 다 적기도 전에 설명부터 해야 합니다. (알선팀장·테스트 계정은 예외)

### 출근 장소 제한

IP 화이트리스트(사무실 네트워크)와 등록된 단말(브라우저)로 가립니다.
**관리자와 일부 직급은 이 제한에서 면제됩니다.** 면제 대상은 화면 어디에도 적지
않습니다 — 적어 두면 "나는 왜 안 되냐"가 됩니다. 코드는
`server/src/attendance/attendance.service.ts` 의 `isPlaceExempt` 입니다.

## 6. 돈 계산식 — `server/src/settlements/settlement.calc.ts`

**이 파일 하나에 모든 계산식이 있습니다.** 화면에도 같은 식이 있는데
(`src/types.ts`), **두 파일의 내용은 글자까지 같아야 합니다.** 한쪽만 고치면
화면과 저장값이 달라지고, 어긋난 쪽이 급여라 사람이 먼저 압니다.

### 이전비 (매입가만 있으면 정해집니다)

```
상사 이전비  = 매입가 × 1%        (최소 5만원, 최대 30만원)
취득세       = 매입가 × 7%          (10원 미만 버림)
추가이전비   = 취득세 × 15%         (취득세가 200만원을 넘을 때만)
이전비 칸    = 상사 이전비 + 추가이전비
```

> 추가이전비는 취득세가 200만원을 넘어야 붙습니다 — 매입가로는 약 2,860만원
> 이상인 차입니다. 흔치 않습니다.

### 매입 정산 총비용

```
총비용 = 매입가 + 이전비 + 구전 + 플랫폼수수료 + 카비어수수료 + 상품화총비용
총합계 = 총비용 + 차량비용(주유·배터리·주차·세차·수리)
판매수익 = 차량판매가 − 총합계
```

**실제지급액(상사)을 적으면 달라집니다.** 상사가 매입가와 추가이전비를 먼저 떼고
통장에 넣어 주므로, 그만큼은 이미 빠져 있습니다.

```
실제지급액이 있으면
  총비용   = 추가이전비를 빼고 계산
  판매수익 = 실제지급액 − (총합계 − 매입가)
```

### 카비어 수수료

한 대당 **10만원** (`CARVIOR_FEE`). 검차 리포트가 붙은 차는 자동으로 붙고,
표에서 체크를 켜고 끌 수 있습니다. 손으로 건드리면 그 값이 이깁니다.

### 알선·수출 정산

```
수익금 = 현금 수수료 + 할부 피 + 보험 피 + 차대금업
정산받을금액 = 수익금 구간별
   100만원 미만 → 5만원 정액
   100만원 이상 → 20%
   200만원 이상 → 30%
```

### 알선 딜러 인센티브 — **이제 화면에서 고칩니다**

구간·요율·근속 기본급·팀장 규칙은 **DB(`IncentiveRule`)에 있고, 관리자가
딜러 인센티브 화면의 [요율표 고치기]에서 바꿉니다.** 코드를 고칠 필요가 없습니다.

```
인센티브 = (월 알선 총액 − 기본급) × 구간 요율
구간은 '기본급을 뺀 금액'으로 고릅니다 (총액이 아닙니다)
```

**적용 시작일로 나눠 쌓입니다.** 요율을 바꿔도 지난달 급여는 그대로입니다 —
그 달에는 그 달에 살아 있던 표로 셈합니다.

### 식대

근태로 냅니다 — **9:30 까지 찍고 18:00 을 넘겨 찍은 날**만 하루 9,000원.
퇴근할 때 "구내식당에서 드셨나요?"를 묻고, 답한 대로 셉니다.
인건비 화면에서 달·사람별로 직접 고칠 수도 있습니다(칸을 비우면 근태 기준으로
돌아갑니다).

### 출퇴근 점수 (월별 순위)

```
9:30 보다 일찍 온 만큼  → 쌓임
18:00 전에 간 만큼      → 깎임
18:30 넘겨 간 만큼      → 쌓임 (하루 2시간까지)
안 찍은 날 → 하루치(9시간) 깎임 / 정정한 날 → 30분 깎임
평일만, 20일로 환산
```

| 팔린 차 사진 정리 | 하루 | `vehicle-photos/vehicle-photos.module.ts` |

### 매입 정산 중복 정리 — 알아 두실 것

같은 차량번호가 두 줄 이상이면 하나만 남기고 나머지에 **하루 뒤 삭제 예정**을
찍습니다. 화면에서 줄이 그어지고 빨갛게 보입니다.

- 남기는 줄: 승인 찍힘 → 결재 올림 → 상품화 명세 많음 → 판매가 적힘 → 먼저 만든 줄
- **승인이 찍힌 줄은 어느 쪽이든 안 지웁니다**
- 되사온 차(90일 넘게 떨어진 건)는 아예 안 잡습니다
- 화면에서 **[남겨두기]** 를 누르면 다시 안 잡습니다

## 8. 알림

### 텔레그램 — 방이 셋입니다

| 방 | 무엇이 가나 | 금액 |
|---|---|---|
| 공지방 | 차 입고·상품화 완료·주차 이동 등 | **안 보냅니다** |
| 입금확인방 | 입금방 화면에서 **손으로 올린** 차량 쪽지 | 보냅니다 |
| 매입방 | 차를 사오면 자동으로 17줄짜리 카드 | 보냅니다 |

**공지방은 전 직원이 봅니다. 금액·정산·인건비는 절대 보내지 않습니다.**
방 번호가 `.env` 에 없으면 **조용히 안 보냅니다** — 공지방으로 흘려보내지 않습니다.
설정 누락이 금액을 새게 하는 쪽으로 기울면 안 되기 때문입니다.

보낸 기록은 `TelegramLog` 에 남고, **입금방** 화면에서 볼 수 있습니다.

### 그 밖

- 브라우저 푸시 (`VAPID_*`)
- 앱 안 알림 (`Notification` 모델, 종 모양 아이콘)
- 실시간 갱신은 Redis + WebSocket

## 10. 문제가 생겼을 때

| 증상 | 먼저 볼 곳 |
|---|---|
| 화면이 안 뜸 | `pm2 list` → `anyone-api` 가 online 인지 |
| 바뀐 게 안 보임 | 브라우저 Ctrl+Shift+R. 그래도면 배포가 됐는지 확인 |
| 텔레그램이 안 감 | `pm2 logs anyone-api` 뜰 때 로그에 방 연결 여부가 찍힙니다 |
| 출근이 안 찍힘 | 사무실 네트워크인지 / 그 브라우저가 단말 등록됐는지 (크롬·엣지는 따로) |
| 배포가 멈춤 | 2장 '배포가 멈추면' |
| 숫자가 이상함 | 6장 계산식. 화면과 서버 두 파일이 같은지 먼저 확인 |

```bash
pm2 logs anyone-api --lines 200   # 최근 로그
pm2 restart anyone-api            # 재시작
pm2 monit                         # 메모리·CPU
```

## 11. 넘겨드리지 못한 것 · 알아 두실 것

솔직하게 적어 둡니다. 나중에 아셔야 손해가 없습니다.

1. **업로드 파일 백업이 없습니다** (1장 참고). 가장 먼저 손보시길 권합니다.
2. **자동 테스트가 없습니다.** 고친 뒤에는 그 화면을 직접 눌러 확인해야 합니다.
3. **결재자·열람자가 이름으로 박혀 있습니다.** 사람이 바뀌면 코드를 고치고
   배포해야 합니다. 자주 바뀔 자리라면 화면에서 관리하도록 바꾸는 것이 낫습니다.
4. **계산식이 두 파일에 중복되어 있습니다** (서버 / 화면). 한쪽만 고치면
   어긋납니다. 공통 패키지로 묶으면 없앨 수 있는 위험입니다.
5. **매입 정산 중복 정리**는 배포 직후 며칠간 한 번 눈으로 봐 주세요. 되사온 차를
   잘못 잡으면 [남겨두기]로 풀 수 있지만, 하루가 지나면 지워집니다.
6. **서버가 한 대입니다.** 그 서버가 멈추면 전부 멈춥니다.

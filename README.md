## 이게 뭔가

카인더(carinder.kr)처럼 **상사 통합관리 프로그램을 여러 상사에게 무료로 주고,
그 안에서 쓰게 되는 카비어 검차로 과금**하는 제품이다.

관리 프로그램 월 3~5만원은 상사 한 곳 영업하는 발품값도 안 되지만, 상사 한 곳이
월 30대를 매입하면 진단비 × 30이다. 평가사 네트워크는 경쟁사가 코드로 복제할 수 없다 —
**프로그램은 미끼가 아니라 유통망이다.**

### 신규 상사에게 주는 v1 — 사람·일정·소통 8개 + 검차

`home` · `notice` · `attendance`(출퇴근) · `workLog`(업무일지) · `approval`(결재) ·
`consultation`(상담) · `chat`(메시지) · `vehicle`(차량관리) + 검차 맡기기

**정산·매입·급여는 일부러 뺐다.** 양식이 상사마다 다르고(애니원 정산식은
`brokerageProfit` 등 네 함수에 박혀 있다) 두 번째 상사부터 "우리 시트지는 다른데요"가
반드시 나온다. 무료로 주는 제품에 그 요구가 붙으면 수익 없이 개발만 하게 되고,
돈 계산이 한 번 틀리면 상사는 프로그램을 통째로 버린다.

주차장·세차·판금 인보이스·광고비는 애니원 단지와 거래처(대산·KS)에 맞춰 만든 것이라
애초에 다른 상사에서 못 쓴다. 코드는 남겨 두고 `Tenant.modules`로 꺼 둔다.

### ⚠ 지금 상태 — 두 번째 상사를 올리면 안 된다

`Tenant` 모델과 `Employee.tenantId`까지만 들어갔다. **나머지 56개 모델에는 상사 구분이
없다** — 두 번째 상사를 올리면 출퇴근·정산·상담·주차장이 전부 섞여 보인다.
다음 할 일이 모델별 스코핑이고, 쿼리를 수백 개 손으로 고치면 한 군데는 반드시 빠지므로
Prisma `$extends` + AsyncLocalStorage로 중앙에서 거는 쪽을 본다(Prisma 6.19).

그때까지 `Tenant` 테이블에는 1번(애니원모터스, 참조용)만 있어야 한다.

## 실행

**백엔드를 먼저 띄워야 합니다** ([server/README.md](server/README.md) 참고).
그다음 프론트를 실행하면 `/api` 요청이 로컬 백엔드(127.0.0.1:3000)로 프록시됩니다.

```bash
npm install
npm run dev
```

> **Node 22.12 이상(또는 20.19+)이 필요합니다.** 그보다 낮은 버전(예: 22.11)에서는 vite 8 / oxlint의
> 네이티브 바이너리가 `npm install` 때 조용히 건너뛰어져서 `Cannot find module '@rolldown/binding-win32-x64-msvc'`
> 같은 에러가 납니다. Node를 올리는 게 정석이고, 임시로는 아래처럼 바이너리를 직접 넣으면 동작합니다.
>
> ```bash
> npm install @rolldown/binding-win32-x64-msvc --no-save --force
> npm install @oxlint/binding-win32-x64-msvc --no-save --force
> ```

로그인은 서버에 등록된 사내 계정으로만 됩니다. 초기 계정은 시드로 만들어지며
(`yoojinwook`, `anwonyong`), 비밀번호는 `server/README.md`의 시드 절차를 따릅니다.
우측 상단 새로고침 버튼으로 서버 데이터를 다시 불러올 수 있습니다.

테스트용 계정은 서버에서 `npm run seed:test` 한 번이면 만들어집니다 — 관리자 `admin`,
일반 직원 `staff`, 둘 다 비밀번호는 `00700!`입니다. 직원 계정은 소셜 연동 없이 바로 로그인되니
직원 화면(본인 것만 보이는 흐름)도 그대로 확인할 수 있습니다.
확인이 끝나면 비밀번호를 바꾸거나 계정을 지우세요.

## 지금까지 만든 것

### 로그인 / 권한
- 카카오·네이버 소셜 로그인, 관리자 계정 로그인 — **전부 목업**(아래 백로그 참고)
- 소셜 로그인 최초 진입 시 사내 직원과 연결하는 단계
- 로그인한 계정의 역할(직원/관리자)에 따라 화면이 달라짐 (더 이상 수동 토글 아님)
- 모바일 반응형 — 데스크탑은 고정 사이드바, 모바일은 햄버거로 여는 오버레이 드로어

### ① 출퇴근 관리
- 실제 출근/퇴근 버튼(오늘 기준). 출근 등록은 **IP + 단말** 두 조건으로 제한할 수 있습니다(관리자 설정)
  - **IP 화이트리스트** — 사무실 네트워크인지까지만 가름. 같은 WiFi의 휴대폰도 공인 IP가 같아 구분 안 됨
  - **출근 단말** — 자리 PC에서 한 번 등록하면 그 브라우저에 키가 저장되고, **그 PC에서만** 출근이 찍힘
  - 각 조건은 등록된 게 있을 때만 적용(둘 다 비어 있으면 전체 허용)
- 근무시간 원형 게이지, 출퇴근 누락 시 관리자 자동 알림
- 직원: 누락된 날 수정요청(사유+시각) 제출 → 관리자: 승인/반려
- **연차/외근·출장 신청** — 직원이 신청 → 관리자 승인 → 캘린더에 반영(연차는 큰 X 표시, 외근은 별도 표시)
- 월별 리스트/캘린더 뷰, 지각·조퇴·누락·연차·외근 통계 카드 및 필터

### ② 알선 상담 관리
- 차량번호/고객명 검색, 상태(진행중/계약/보류/종결) 필터
- 고객명 클릭 → 해당 고객의 전체 상담 이력 타임라인
- 다음 연락 예정일, 첨부파일 이름(업로드 없이 이름만, 목업)
- 담당자별 상담→계약 전환율, 리스트/캘린더 뷰

### ③ 정산 관리
탭 3개(**알선 정산 / 매입 정산 / 간편 정산**)로 나뉩니다. 금액 단위는 전부 **만원**이고,
각 탭마다 상태·담당자 필터, 차량번호·차량명 검색, 합계 카드, 엑셀(.xlsx) 다운로드가 따로 있습니다.
엑셀은 아래 시트지 컬럼명·순서 그대로 나갑니다.

**알선 정산** — 일자 / 차량번호 / 차량명 / 총 진행 판매금액 / 실차주입금 / 수익금 / 이전비 /
이전비 잔액 / 현금 수수료 / 할부 피 / 보험 피 / 기타비용 / 판매 수익 / 정산받을금액

- `수익금 = 총 진행 판매금액 − 실차주입금` (자동)
- `판매 수익 = 수익금 + 이전비 잔액 + 현금 수수료 + 할부 피 + 보험 피 − 기타비용` (자동)
- 정산받을금액은 직접 입력, **비워두면 판매 수익이 그대로 들어감**

**매입 정산** — 일자 / 차량명 / 차량번호 / 이전비+추가이전비 / 매입가 / 광택 및 세차 /
판금 및 덴트 / 성능비 / 탁송비 / 수리비 / 구전 / 진단비 / 상품화총비용 / 매입+상품화총비용 /
정산금액 / 신차이름

- `상품화총비용 = 광택및세차 + 판금및덴트 + 성능비 + 탁송비 + 수리비 + 구전 + 진단비` (자동, **이전비 제외**)
- `매입+상품화총비용 = 매입가 + 상품화총비용` (자동)
- 정산금액은 직접 입력, **비워두면 매입+상품화총비용이 그대로 들어감**

> 자동계산 식은 폼 안에도 그대로 적어놨습니다(계산 결과 밑의 회색 글씨).
> 실제 시트지와 식이 다르면 [src/types.ts](src/types.ts)의 `brokerageProfit` / `brokerageSaleProfit` /
> `purchasePrepTotal` / `purchaseGrandTotal` 네 함수만 고치면 표·폼·엑셀에 한 번에 반영됩니다.

**간편 정산** — 기존에 쓰던 매입가/상품화비용/판매금액/수수료 → 순이익 자동계산 양식.
새 시트지 두 개로 대체되는 자리라, 안 쓰시면 탭째로 걷어내면 됩니다.

### ⑦ 차량 관리
탭 2개(**외부 이동 차량 / 주유·배터리 비용**)입니다.

**외부 이동 차량** — 매입되어 단지로 들어온 차량을 등록하고, 체크박스 3개로 상태를 관리합니다.

- 차량번호는 **`12가3456` / `123가4567` 두 형식만** 저장됩니다 (형식 외 입력 시 저장 불가)
- 체크 조합으로 리스트가 자동으로 갈립니다 — 분류값은 저장하지 않고 매번 계산합니다

| 상품화 | 광고 완료 | 외부 이동 금지 | 분류 |
|:--:|:--:|:--:|---|
| ☐ | ☐ | ☐ | 상품화 대기 |
| ☑ | ☐ | ☐ | 광고 예정 |
| ☑ | ☑ | ☐ | **외부 이동 가능** (광고 예정에서 빠짐) |
| — | — | ☑ | **이동금지** (다른 체크와 무관한 최우선 플래그) |

- 상품화가 안 켜져 있으면 광고완료 체크박스는 **비활성화**되고, 상품화를 끄면 광고완료도 함께 꺼집니다
- 체크박스 조작은 **전 직원** 가능
- 필터 칩(전체/상품화 대기/광고 예정/외부 이동 가능/이동금지)으로 각 리스트를 바로 볼 수 있고, 칩에 건수가 같이 표시됩니다

**주유 · 배터리 비용** — 차량번호 **뒤 4자리만** 넣으면 차종이 자동으로 채워집니다.

- 차종이 잡히면 그때 금액 입력칸이 열립니다. 날짜는 등록 시점으로 자동 저장
- 비고(상품중/시승중/판매완료)는 **주유에만** 있습니다
- 같은 뒷자리 차가 여러 대면 **전체 차량번호 + 차종이 함께 보이는 선택박스**가 뜹니다
- 등록할 때마다 별도 로그 테이블에 이력이 쌓이고, 나중에 수정·삭제할 수 있습니다
- 종류·월 필터와 합계 금액 표시

오류 문구:

| 상황 | 메시지 |
|---|---|
| 뒤 4자리로 못 찾음 | 차량번호를 다시 확인해주세요. |
| 선택박스가 떴는데 미선택 | 차량번호 선택박스를 체크해주세요. |
| 이미 등록된 번호 | 동일한 차량번호가 있습니다. |
| 번호 형식 오류 | 차량번호 형식을 확인해주세요. |

> **재검 리스트는 보류** 상태입니다 — 카모두 API가 없고 웹 HTML 연동이 막혀 있어 추후 별도 논의.
> 금액 단위는 정산(만원)과 달리 **원**입니다. 주유비가 만원 단위로 안 떨어져서 그렇습니다.

### ⑧ 실시간 알림 · 메시지 (socket.io)
- 브라우저를 열어둔 사람에게 **새로고침 없이** 알림이 뜹니다 — 우측 아래 토스트 + 알림 목록 즉시 갱신
- **승인/반려 결과 알림 추가** — 그전에는 관리자에게만 알림이 갔고, 직원은 결과를 알림으로 못 받았습니다
- **관리자 ↔ 직원 메시지** — 사이드바 '메시지'
  - 관리자: 왼쪽에 전 직원 목록(대화 없는 직원도 나와서 먼저 말을 걸 수 있음), 안읽음 배지·마지막 메시지 표시
  - 직원: 관리자와의 대화 하나가 바로 열림
  - Enter 전송 / Shift+Enter 줄바꿈, **읽음 표시**, 사이드바에 안읽음 개수 배지
  - 대화는 **직원 한 명당 하나** — 관리자 여러 명이 같은 대화에 들어와 답하는 구조

> 소켓 인증은 HTTP와 같은 JWT를 씁니다. 로그인 상태에서만 붙고 로그아웃하면 끊습니다.
> 배포 시 Apache에 `proxy_wstunnel`과 `/socket.io` 프록시 설정이 필요합니다
> (`server/README.md`의 ⑧ 항목 참고). 안 해도 롱폴링으로 동작하지만 WebSocket이 낫습니다.

## 백로그 (아직 안 한 것)

- **카카오/네이버 실제 로그인 연동** — 서버는 소셜 계정을 받아 직원과 연결하는 부분까지 준비돼 있고
  (`POST /api/auth/social`, `/api/auth/link`), 프론트에서 카카오·네이버 SDK를 붙이는 일만 남았습니다.
  개발자센터에서 앱 등록하고 키 받아오시면 `src/lib/auth.ts`의 `loginWithSocial` 앞단만 채우면 됩니다.
- **채팅 추가 기능** — 1:1 텍스트는 됩니다(⑧ 참고). 파일 첨부, 여러 명 단체방,
  브라우저를 닫아둔 사람에게 푸시(Web Push)는 아직입니다
- **정산 개별 PDF 출력** — 요청안에 있던 항목인데 아직 미구현(엑셀만 됨)
- **주차장 구역도 시각적 배치 개선** — 지금은 표 형태 재현. 실제 도면처럼 더 그래픽적으로 만드는 건 다음 단계
- **통화녹음 자동 STT/AI요약 (상담 자동화)** — Channel Talk Meet 같은 기능 논의만 하고 보류 중.
  실제로 붙이려면 통화녹음 인프라(PBX 연동 등) + 녹음 고지·동의(통신비밀보호법) 검토 필요
- **정산/주차장 모듈에 캘린더뷰 미적용** — 출퇴근/상담에만 있음, 필요하면 추가 가능
